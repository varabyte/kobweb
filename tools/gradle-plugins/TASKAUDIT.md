# Gradle Task Audit

An audit of every task registered by the Gradle code under `tools/gradle-plugins`. Tasks are grouped by the plugin
(or build script) that registers them. Tasks marked "(kobweb group)" extend `KobwebTask`, which assigns them to the
`kobweb` Gradle task group.

## `core` – `com.varabyte.kobweb.core` plugin

### `kobwebGenerateModuleMetadata`
(`KobwebGenerateModuleMetadataTask`, `KobwebCorePlugin`)
Generates a `module.json` metadata file that is bundled into the project's jar, identifying the artifact as one built
by Kobweb. Libraries, workers, and applications all pick it up through the core plugin.

## `application` – `com.varabyte.kobweb.application` plugin

### Code generation (`KobwebGenerateTask` subclasses; all run by `kobwebGenAll`)

- **`kobwebGenSiteIndex`** (`KobwebGenerateSiteIndexTask`): Generates the site's `index.html` from the `app.index`
  configuration, `conf.yaml`, and dependencies' index contributions. Cacheable.
- **`kobwebGenSiteEntry`** (`KobwebGenerateSiteEntryTask`): Generates the Kotlin entry point (`main.kt`) for the
  frontend. It wires up routes, globals, and app init from the cached frontend data. Registered once per JS target and
  cacheable.
- **`kobwebGenApisFactory`** (`KobwebGenerateApisFactoryTask`): Generates server-side code registering all `@Api`
  endpoints into an `ApisFactory`. It is added as a source dir of the JVM target and excluded from KSP. It fails early
  if `kobweb-api` isn't a dependency. Registered per JVM target.
- **`kobwebGenAll`** (plain task, group `kobweb`): A convenience task that depends on every `KobwebGenerateTask`, so all
  `kobwebGen...` tasks can be run at once.

### Data caching (plain `DefaultTask`, cacheable)

- **`kobwebCacheAppFrontendData`** (`KobwebCacheAppFrontendDataTask`): Merges the app's own KSP frontend metadata with
  that of all dependency jars into `appData.json` under the `.kobweb` cache. Downstream tasks (site entry, export,
  list routes, etc.) read this file instead of rescanning. Per JS target.
- **`kobwebCacheAppBackendData`** (`KobwebCacheAppBackendDataTask`): The backend counterpart, merging API metadata from
  the app and its dependencies. The input file is optional since a JVM target may not exist. Per JVM target.

### Resource copying (`KobwebCopyTask` subclasses)

- **`kobwebCopySupplementalResources`** (`KobwebCopySupplementalResourcesTask`): Copies the generated `index.html` and
  `public/` resources from Kobweb libraries into the final site's resources. Not cached, since it's a plain copy.
- **`kobwebCopyWorkerJsOutput`** (`KobwebCopyWorkerJsOutputTask`): Copies JS output from Kobweb worker dependencies into
  the final site's resources. *Note:* the `worker` plugin registers a different task with the same name (see below).
- **`kobwebCreateDevPublicFiles`** (`KobwebCreatePublicDevFilesTask`): Creates dev-only files in the `public` folder so
  the dev server can see them.

### Server setup and lifecycle

- **`kobwebUnpackServerJar`** (`KobwebUnpackServerJarTask`): Extracts the `server.jar` embedded in the Gradle plugin
  into the `.kobweb` folder.
- **`kobwebCreateServerScripts`** (`KobwebCreateServerScriptsTask`): Creates scripts that start the Kobweb server in
  production mode, based on the export site layout.
- **`kobwebSyncServerPluginJars`** (`Sync`, group `kobweb`): Syncs the jars in the `kobwebServerPlugin` configuration
  into `.kobweb/server/plugins`. It deletes stale jars from the destination.
- **`kobwebStart`** (`KobwebStartTask`): Starts a Kobweb server in dev or prod mode, and supports remote debugging, system
  properties, and server reuse (`-PkobwebReuseServer`, default true). Untracked. Build scripts are added as inputs so
  continuous mode reacts to them. In dev mode, it fails if the configured dev script is missing, and it depends on the
  JVM jar when there is a JVM target.
- **`kobwebStop`** (`KobwebStopTask`): Stops a running Kobweb server, if any.

### Export and utilities

- **`kobwebExport`** (`KobwebExportTask`): Exports the project into a static site, running the server and using
  Playwright to snapshot each route. Untracked. It uses cached frontend and backend data and the export layout, and
  it depends on the production webpack build.
- **`kobwebListRoutes`** (`KobwebListRoutesTask`): Prints all routes Kobweb manages for the site to the console.
- **`kobwebBrowserCacheId`** (`KobwebBrowserCacheIdTask`): Prints `<browser>-<playwright version>` so that CI can use
  it as a cache key (e.g. `./gradlew -q kobwebBrowserCacheId`). *Note:* its description is copy-pasted from
  `kobwebExport` ("Export the Kobweb project into a static site") and is wrong.
- **`kobwebCleanSite`** (`KobwebTask`, inline actions): Deletes artifacts generated by a previous export, i.e. the
  prod site root and the trace output folder, if configured.
- **`kobwebCleanFolder`** (`KobwebTask`, inline actions): Deletes the `.kobweb/server` folder. It depends on
  `kobwebCleanSite`.

## `library` – `com.varabyte.kobweb.library` plugin

### `kobwebGenerateLibraryMetadata`
(`KobwebGenerateLibraryMetadataTask`)
Generates a `library.json` file into the jar's metadata, which identifies the artifact as a Kobweb library. It includes
the serialized `index` head from the `library` block, and the output is added as a resource dir of each JS target.

## `worker` – `com.varabyte.kobweb.worker` plugin

- **`kobwebGenerateWorkerMetadata`** (`KobwebGenerateWorkerMetadataTask`): Generates a `worker.json` file into the jar's
  metadata, identifying the artifact as a Kobweb worker. It is added to the JS target's `processResources`.
- **`kobwebCopyWorkerJsOutput`** (`Sync`, per JS target): Copies the `*.js` files (no source maps) from the browser
  distribution into `build/generated/kobweb/worker/output` under the worker metadata subfolder, then packages them
  in the JS jar. It is wired into the jar rather than `processResources` because webpack runs after the latter.
  *Note:* it shares a name with the application plugin's `KobwebCopyWorkerJsOutputTask` (which consumes this output).
  The two plugins are not normally applied to the same project.

## `extensions/markdown` – `com.varabyte.kobwebx.markdown` plugin

Both tasks share the `MarkdownTask` base class, which receives the page package, project group, and markdown folders.

- **`kobwebxMarkdownProcess`** (`ProcessMarkdownTask`): Runs the user's `process` callback from the `markdown` block,
  letting them generate extra source or resource files (e.g. indexes or feeds) from all markdown files.
- **`kobwebxMarkdownConvert`** (`ConvertMarkdownTask`): Converts markdown files in the resources path into Kotlin
  `@Page` composable sources, applying the configured handlers, features, and front matter. Output goes to the
  generated JS source dir.

## Build scripts of the plugin projects themselves

- **`generateVersionProperties`** (`core/build.gradle.kts`): Writes `version.properties` containing the project version
  and adds it to the plugin's resources, so that plugin code can find the Kobweb version at runtime.
- **`copyServerJar`** (`application/build.gradle.kts`, `Sync`): Copies the shadow jar of the Kobweb server, renamed to
  `server.jar`, into `build/generated/kobweb/server` and adds it to the plugin's resources. This is what
  `kobwebUnpackServerJar` later extracts.

## Notes

- `KobwebCopyTask`, `KobwebGenerateTask`, `MarkdownTask`, and `KobwebTask` are abstract base classes and are never
  registered directly. (`KobwebTask` is registered directly only for `kobwebCleanSite` and `kobwebCleanFolder`.)

## Gradle plugins relied upon

This covers third-party/JetBrains Gradle plugins used by the plugin projects, either at runtime (the plugin code
interacts with them in a user's build) or at build time (the build logic that compiles and publishes the plugins).

### Runtime dependencies (used by the Kobweb plugins in a user's build)

- **Kotlin Gradle Plugin / Kotlin Multiplatform (`org.jetbrains.kotlin.multiplatform`)**: Every Kobweb plugin
  is `compileOnly` against `kotlin("gradle-plugin")` and expects the user to have applied it. The plugins use it to
  find the JS and JVM targets, their source sets, compilations, classpaths, and tasks (`processResources`,
  `jar`, webpack, browser run/distribution), and to add generated source and resource dirs.
- **KSP (`com.google.devtools.ksp`)**: The core plugin depends on it (`implementation(libs.ksp.plugin)`)
  and applies it itself (`applyKspPlugin`). It runs the Kobweb processors that discover pages, APIs, workers, and
  so on, and produces the metadata that the `kobwebCache…` tasks merge.
- **Compose Compiler Gradle plugin (`org.jetbrains.kotlin.plugin.compose`)**: Not applied by Kobweb; the core
  plugin reacts to it via `pluginManager.withPlugin` and, unless disabled with `kobweb.configureComposeCompiler=false`,
  configures its extension for smaller and faster sites. It is `compileOnly`, and failure to configure it only
  produces a warning.
- **Kotlin Serialization compiler plugin (`org.jetbrains.kotlin.plugin.serialization`)**: Applied to the plugin projects
  themselves, so that they can serialize their JSON metadata. It is not applied to user projects.
- **Gradle Kotlin DSL (`gradleKotlinDsl()`)**: Not a plugin but an API that the core plugin exposes
  (`compileOnlyApi`) for its configuration blocks.

### Build-time dependencies (building and publishing the plugins)

- **Kotlin JVM (`org.jetbrains.kotlin.jvm`)**: Compiles each plugin project.
- **Gradle Plugin Publish (`com.gradle.plugin-publish`)**: Applied through the `kobweb-gradle-portal` convention
  plugin. It publishes to the Gradle Plugin Portal and sets website, VCS, and tags. `publishPlugins` is disabled for
  `-SNAPSHOT` versions.
- **`java-gradle-plugin`**: Provides the `gradlePlugin { plugins { … } }` blocks that declare `kobwebCore`,
  `kobwebApplication`, `kobwebLibrary`, `kobwebWorker`, and `kobwebxMarkdown`. It is brought in automatically by
  the plugin-publish plugin.
- **Kotlin SAM-with-receiver and Assignment compiler plugins**: Applied in the `kobweb-compilation-settings`
  convention so that Gradle Kotlin DSL idioms (e.g. `=` for properties) work in the plugin code.
- **`com.varabyte.kobweb.internal.publish` (`KobwebPublishPlugin`)**: The repo's own publishing convention. It applies
  the two plugins below and is used by every plugin project.
  - **Dokka (`org.jetbrains.dokka`)**: Generates the Javadoc/HTML docs jars that Maven Central requires.
  - **Vanniktech Maven Publish (`com.vanniktech.maven.publish`)**: Handles Maven publishing, POM metadata, and signing.
- **Shadow (`com.gradleup.shadow`)**: Not used by the plugin projects directly. It is applied in
  `backend/server` to build the fat server jar that the `application` project's `copyServerJar` task embeds as
  `server.jar` (the `shadow` configuration is consumed via the `serverJar` configuration).
